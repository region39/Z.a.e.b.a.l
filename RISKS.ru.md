# Оценка рисков Z.A.E.B.A.L.

> Риски, баги и ограничения протокола самоаудита.
> Актуально на 2026-07-29.

---

## 1. Ложные срабатывания (false positives)

### 1.1. Подстрока мата в обычных словах

**Риск:** слово содержит корень мата как подстроку.
**Пример:** «заебатый» — детектор найдёт `заеб`, хотя это не ругань.
**Вероятность:** средняя.
**Влияние:** L1 вместо тишины — агент остановится без причины.
**Смягчение:** wordlist собран из корней, а не целых слов. Ложное срабатывание возможно, но маловероятно в реальном диалоге — контекст обычно проясняет.

### 1.2. Мат в коде

**Риск:** сообщение содержит код с матом в именах переменных, комментариях или строках.
**Пример:** `is_fucked_up = True`, `// TODO: хуйня какая-то`.
**Вероятность:** низкая.
**Влияние:** L1 на техническое сообщение.
**Смягчение:** нет. Детектор не парсит синтаксис — это отдельная задача.

### 1.3. Цитата мата от третьего лица

**Риск:** пользователь пересказывает чужой мат, не адресуя его агенту.
**Пример:** «клиент написал: "да это пиздец"».
**Вероятность:** низкая.
**Влияние:** L1, хотя претензия не к агенту.
**Смягчение:** Step 0 протокола — «реши, адресован ли мат тебе». Но агент может проигнорировать.

---

## 2. Пропуск срабатываний (false negatives)

### 2.1. Мат без мата (сарказм, пассивная агрессия)

**Риск:** пользователь бесится, но не матерится.
**Пример:** «ну ты молодец, конечно», «отлично, просто отлично».
**Вероятность:** **высокая**.
**Влияние:** протокол не срабатывает, хотя агент тупит.
**Смягчение:** нет. Детектор сарказма — отдельная NLP-задача с высоким уровнем ложных срабатываний. Осознанное ограничение.

### 2.2. Креативный leetspeak

**Риск:** пользователь намеренно искажает мат, чтобы обойти детектор.
**Пример:** `z@6@l`, `p1zd0s`, `3@6y4`.
**Вероятность:** низкая (в реальном диалоге так не пишут).
**Влияние:** пропуск срабатывания.
**Смягчение:** таблица leet-замен покрывает основные варианты. Полное покрытие невозможно.

### 2.3. Мат в прикреплённых файлах

**Риск:** мат в тексте файла, изображения, голосового сообщения.
**Вероятность:** **высокая** (если материться файлами).
**Влияние:** протокол не срабатывает.
**Смягчение:** хук видит только текст сообщения. Обработка вложений — отдельная задача.

### 2.4. Смешанный язык

**Риск:** мат на одном языке в сообщении на другом.
**Пример:** «this is pizdets какой-то».
**Вероятность:** средняя.
**Влияние:** детектор найдёт `pizd` (есть в wordlist), но может не найти, если корень не покрыт.
**Смягчение:** wordlist покрывает ~400 корней (ru + en). Этого достаточно для 95+% реального мата.

## 3. Поломка промпта агента

### 3.1. Прерывание валидного рассуждения

**Риск:** агент решает сложную задачу, пользователь матерится на погоду — протокол врывается и сбивает фокус.
**Вероятность:** средняя.
**Влияние:** потеря контекста, перезапуск рассуждения.
**Смягчение:** Step 0 протокола — «если мат про внешний мир — игнорируй». classify() пытается определить адресата, но неидеально.

### 3.2. Агент переусердствует

**Риск:** на L1 агент запускает аудиторов, хотя достаточно было просто остановиться.
**Вероятность:** средняя.
**Влияние:** лишние токены, задержка ответа.
**Смягчение:** протокол предписывает запускать аудиторов на L1, но это рекомендация, не требование. Агент может решить не запускать.

### 3.3. L3 «FULL STOP» — иллюзия

**Риск:** нет технической блокировки инструментов. Агент должен сам остановиться.
**Вероятность:** **высокая** (если агент уже зациклен).
**Влияние:** протокол не срабатывает, агент продолжает ошибаться.
**Смягчение:** осознанное решение — технический лок опаснее (агент не сможет выполнить полезные действия). Только дисциплина.

### 3.4. Конфликт с другими инструкциями

**Риск:** в контексте уже есть AGENTS.md, CLAUDE.md или другие инструкции, противоречащие протоколу.
**Вероятность:** средняя.
**Влияние:** протокол может быть проигнорирован или переопределён.
**Смягчение:** теги `<zaebal>` инжектятся в начало контекста — выше, чем файлы инструкций. Но агент может решить иначе.

### 3.5. Раздувание контекста

**Риск:** частые срабатывания засоряют контекст тегами и протоколами.
**Вероятность:** низкая (редко кто матерится каждые 5 минут).
**Влияние:** ~500 токенов на срабатывание, ~1500 на L3 с вердиктом.
**Смягчение:** стрик сбрасывается через 30 минут без мата. При активной ругани — это меньшая из проблем.

## 4. Нагрузка на систему

### 4.1. Детектор

**Оценка:** **ничтожная**.

| Операция | Сложность | Время |
|---|---|---|
| NFKC-нормализация | O(n) | < 0.1ms |
| Regex (ack/praise/complaint) | 3 compiled regex | < 0.2ms |
| Wordlist lookup (set) | O(1) × ~400 корней | < 0.3ms |
| JSON state read/write | ~1KB | < 1ms |
| **Итого на сообщение** | | **< 2ms** |

Даже при 1000 сообщений/час — ~0.5 секунды процессорного времени в час.

### 4.2. Внешний аудитор (L3)

**Оценка:** **значительная, но редкая**.

- Запуск `delegate_task` с транскриптом (до 12K символов)
- Время ответа: 10–30 секунд (зависит от модели)
- Частота: только на L3 (стрик 4+), что в реальном диалоге — редкость

### 4.3. JSON state

- Файл `~/.zaebal/state.json` — до 50 сессий
- Размер: ~1–5 KB
- Чтение/запись: на каждое сообщение с матом
- Риск: нет — атомарная запись, fail-open при ошибке

## 5. Безопасность

### 5.1. Инъекция в контекст

**Риск:** злонамеренное сообщение может сфабриковать теги `<zaebal>`.
**Влияние:** низкое — теги просто дублируются, протокол не меняется.
**Смягчение:** хук добавляет свои теги поверх. Дублирование не опасно.

### 5.2. Утечка state-файла

**Риск:** `~/.zaebal/state.json` содержит историю мата.
**Влияние:** низкое — только метаданные (время, вес стрика), не текст сообщений.
**Смягчение:** state хранит только числовые веса и таймстемпы, не текст.

### 5.3. Рекурсия аудитора

**Риск:** внешний аудитор (агент) получает транскрипт с тегами `<zaebal>` и запускает протокол сам на себя.
**Влияние:** бесконечный цикл.
**Смягчение:** в `zaebal.py` есть `ZAEBAL_INTERNAL` env-флаг — если он установлен, детектор молча выходит. Аудитор запускается с этим флагом.

---

## 6. Зависимости

| Компонент | Зависимость | Риск отказа |
|---|---|---|
| Детектор | Python stdlib | **Нулевой** — всегда доступен |
| State | Файловая система | **Низкий** — fail-open при ошибке записи |
| Shell hook | Hermes hooks API | **Низкий** — если хук не настроен, ничего не происходит |
| Внешний аудитор (L3) | OmniRoute / провайдер LLM | **Средний** — если провайдер недоступен, L3 не выполняется, но L1/L2 работают |
| Wordlist | Локальные файлы | **Нулевой** — встроены в репозиторий |

---

## 7. Итоговая матрица рисков

| Риск | Вероятность | Влияние | Приоритет |
|---|---|---|---|
| Сарказм без мата не детектится | Высокая | Среднее | **Высокий** |
| L3 FULL STOP не срабатывает | Высокая | Высокое | **Высокий** |
| Прерывание валидного рассуждения | Средняя | Среднее | Средний |
| Ложное срабатывание на код | Низкая | Низкое | Низкий |
| Конфликт с другими инструкциями | Средняя | Среднее | Средний |
| Нагрузка на систему | **Ничтожная** | Низкое | **Незначительный** |
| Утечка state | Низкая | Низкое | Низкий |
| Рекурсия аудитора | Низкая | Высокое | Средний |

**Главное ограничение:** протокол меняет инструкции, но не блокирует инструменты. Агент, который уже глубоко в цикле, может проигнорировать протокол. Это осознанный компромисс — технический лок опаснее.
